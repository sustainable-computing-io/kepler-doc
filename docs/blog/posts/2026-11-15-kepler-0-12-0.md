# Kepler 0.12.0 and Kepler Operator 0.25.0

**Author:** Granite Tait

Kepler 0.12.0 came out on September 22. It lets you choose which CPU power meter Kepler uses,
falls back to HWMON on machines without RAPL, and adds experimental power attribution for NVIDIA
MIG instances. It also adds health probes, detects more kinds of VMs, and warns you about config
keys it doesn't recognize.

Kepler Operator 0.25.0 followed on October 19. It deploys Kepler 0.12.0 and fixes a Helm chart bug
that kept installing an old operator and an old Kepler.

> **Release notes:** [Kepler v0.12.0](https://github.com/sustainable-computing-io/kepler/releases/tag/v0.12.0)
> and [Kepler Operator v0.25.0](https://github.com/sustainable-computing-io/kepler-operator/releases/tag/v0.25.0)

## Highlights

### Kepler

- **Pick your CPU power meter.** `cpu.preferredMeters` sets the order, and HWMON is the fallback when RAPL isn't there ([#2468](https://github.com/sustainable-computing-io/kepler/pull/2468), [#2471](https://github.com/sustainable-computing-io/kepler/pull/2471), [#2440](https://github.com/sustainable-computing-io/kepler/pull/2440))
- **NVIDIA MIG power attribution (experimental)** via dcgm-exporter ([#2422](https://github.com/sustainable-computing-io/kepler/pull/2422))
- **Liveness and readiness probes** on their own endpoints ([#2511](https://github.com/sustainable-computing-io/kepler/pull/2511))
- **VirtualBox, VMware and Xen VMs** are now detected, not only QEMU/KVM ([#2515](https://github.com/sustainable-computing-io/kepler/pull/2515))
- **Unknown config keys get a warning** instead of being dropped silently ([#2536](https://github.com/sustainable-computing-io/kepler/pull/2536))

### Kepler Operator

- **Kepler 0.12.0** is the new default ([#694](https://github.com/sustainable-computing-io/kepler-operator/pull/694))
- **Helm installs get the versions they ask for.** Charts 0.22.2 through 0.24.0 deployed operator 0.21.0 and Kepler v0.11.0 ([#699](https://github.com/sustainable-computing-io/kepler-operator/pull/699), [#694](https://github.com/sustainable-computing-io/kepler-operator/pull/694))
- **OpenTelemetry Go modules updated** to v1.41.0 for CVE-2026-24051, which only affects macOS ([#673](https://github.com/sustainable-computing-io/kepler-operator/pull/673))
- **Full user docs in the operator repository** ([#698](https://github.com/sustainable-computing-io/kepler-operator/pull/698))

**Upgrade notes:** `experimental.hwmon.enabled` is gone, and Xen guests get new label values.
Read the [upgrade notes](#upgrade-notes) before you upgrade.

## Kepler 0.12.0

### Choosing CPU power meters

`cpu.preferredMeters` lists CPU power meter backends in order. Kepler uses the first one that
starts and reports zones. It picks once at startup and doesn't switch later. The default is
`[rapl, hwmon]`, so machines without RAPL, like ARM nodes, fall back to HWMON on their own:

```yaml
cpu:
  preferredMeters:
    - rapl
    - hwmon
```

HWMON also got better. It reads energy counters when the hardware exposes them, before power or
current and voltage readings ([#2428](https://github.com/sustainable-computing-io/kepler/pull/2428)).
See the [configuration guide](https://github.com/sustainable-computing-io/kepler/blob/v0.12.0/docs/user/configuration.md)
for all the options. Some of its examples use `cpu.meters`, a name no Kepler release reads.
Use `cpu.preferredMeters`.

### NVIDIA MIG power attribution (experimental)

On GPUs split into MIG instances, Kepler now uses activity data from dcgm-exporter to divide a
GPU's power between its instances, and then between the processes in each instance. Point it at
the DCGM exporter on the same node, or leave `dcgmEndpoint` empty and Kepler finds the local exporter pod:

```yaml
experimental:
  gpu:
    enabled: true
    dcgmEndpoint: ""
```

If you run the NVIDIA GPU Operator and install Kepler with Helm, turning on GPU monitoring now
adds an init container that copies only the NVML libraries into the Kepler pod
([#2489](https://github.com/sustainable-computing-io/kepler/pull/2489)). Before, the chart didn't
mount the NVIDIA libraries, and the plain manifests mounted the whole driver root, whose glibc
broke NVML loading. The plain manifests now use the same init container.

### Health probes

Kepler serves `/probe/livez` and `/probe/readyz`. They don't compute any power, so they are cheap
to call. Kepler is ready once all of its services have started. The Kepler Helm chart wires both up as the DaemonSet's liveness and readiness
probes.

### More VM detection

Kepler used to recognize only QEMU/KVM guests. It now also detects VirtualBox, VMware and Xen
VM processes, so their power shows up at the VM level.

### A warning for unknown config keys

Before 0.12.0, Kepler dropped config keys it didn't know without saying anything. A typo, or an
option from another release, just vanished. Kepler now logs them at startup. For example, the old
`experimental.hwmon.enabled` key shows up like this:

```text
level=WARN msg="ignoring unknown config fields; check for typos or options from another release" fields=[enabled]
```

### Bug fixes

- `node_name` is no longer empty when Kepler runs outside Kubernetes ([#2444](https://github.com/sustainable-computing-io/kepler/pull/2444))
- `kepler_container_cpu_seconds_total` is now exported ([#2501](https://github.com/sustainable-computing-io/kepler/pull/2501))
- Power is attributed with the current snapshot's CPU usage instead of the previous one ([#2452](https://github.com/sustainable-computing-io/kepler/pull/2452))
- A `permission denied` on `/proc` now tells you Kepler needs root or `CAP_SYS_PTRACE` ([#2547](https://github.com/sustainable-computing-io/kepler/pull/2547))
- The Helm chart honors `serviceAccount.create` ([#2533](https://github.com/sustainable-computing-io/kepler/pull/2533))
- DCGM endpoint discovery reads the port from the pod spec and reports why an endpoint can't be reached ([#2432](https://github.com/sustainable-computing-io/kepler/pull/2432), [#2497](https://github.com/sustainable-computing-io/kepler/pull/2497))

### Kepler under the hood

These changes aren't listed under "What's Changed" in the generated release notes:

- **HWMON skips disabled sensors** when the hardware marks them off ([#2427](https://github.com/sustainable-computing-io/kepler/pull/2427))
- **The Redfish client library was updated** for its recent refactor ([#2401](https://github.com/sustainable-computing-io/kepler/pull/2401))
- **No more GPU logs** when GPU monitoring is turned off ([#2415](https://github.com/sustainable-computing-io/kepler/pull/2415))
- **Dependencies updated** for Go 1.24 ([#2516](https://github.com/sustainable-computing-io/kepler/pull/2516))

The ARM64 build support in [#2442](https://github.com/sustainable-computing-io/kepler/pull/2442)
lets you build Kepler for arm64 yourself. The published `kepler:v0.12.0` image is still amd64 only.

## Kepler Operator 0.25.0

### Kepler 0.12.0 settings through ConfigMaps

The operator deploys Kepler 0.12.0 and passes the new settings through
[additional ConfigMaps](https://github.com/sustainable-computing-io/kepler-operator/blob/v0.25.0/docs/user/reference/custom-configmaps.md).
Put the Kepler config in a ConfigMap. For example, to use only HWMON:

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: kepler-cpu-config
  namespace: power-monitor
data:
  config.yaml: |
    cpu:
      preferredMeters:
        - hwmon
```

Then list it under `spec.kepler.config.additionalConfigMaps` in your `PowerMonitor`:

```yaml
spec:
  kepler:
    config:
      additionalConfigMaps:
        - name: kepler-cpu-config
```

### The Helm chart was installing operator 0.21.0

The release workflow updated the chart version on each release but left `operator.image` behind.
Charts 0.22.2 through 0.24.0 all pointed at operator `0.21.0` and set `kepler.image` to `v0.11.0`.
If you installed with Helm in that window, you were running operator 0.21.0 and Kepler v0.11.0.
Operator 0.24.0 installed through OLM ran Kepler 0.11.4. If you were on chart 0.24.0, you also missed
the operator 0.24.0 change that swapped `privileged` for `CAP_SYS_PTRACE` on the Kepler pods ([#651](https://github.com/sustainable-computing-io/kepler-operator/pull/651)).

Chart 0.25.0 deploys operator 0.25.0 and Kepler v0.12.0. The release workflow now bumps the image
together with the chart, and a validation script checks that they match.

Check which operator you are running:

```bash
kubectl get deploy -n kepler-operator -o jsonpath='{.items[*].spec.template.spec.containers[*].image}'
```

### Full user docs in the operator repository

The OpenShift install, configuration, troubleshooting and migration guides from this site
now also live next to the code in [`docs/user`](https://github.com/sustainable-computing-io/kepler-operator/tree/v0.25.0/docs/user).
They were checked against the current APIs and security defaults on the way over.

### Operator under the hood

These changes don't show up in the generated release notes:

- **ARM64 build tooling.** The Dockerfile and Makefile can now cross-compile the operator and bundle
  for amd64 and arm64 ([#667](https://github.com/sustainable-computing-io/kepler-operator/pull/667)).
  The published 0.25.0 operator image is still amd64 only.
- **E2E tests moved to Ginkgo and Gomega**, following the Operator SDK recommendation ([#649](https://github.com/sustainable-computing-io/kepler-operator/pull/649))
- **Dependencies updated** for Go 1.24 ([#693](https://github.com/sustainable-computing-io/kepler-operator/pull/693))

## Upgrade notes

### `experimental.hwmon.enabled` is gone

In Kepler 0.11.4, `experimental.hwmon.enabled: true` made Kepler use HWMON instead of RAPL. Kepler
0.12.0 renamed it to `experimental.hwmon.forceEnabled` ([#2440](https://github.com/sustainable-computing-io/kepler/pull/2440)),
and then deprecated that in favor of `cpu.preferredMeters`
([#2468](https://github.com/sustainable-computing-io/kepler/pull/2468)). If you still set the old
key, HWMON is no longer forced and Kepler goes back to RAPL wherever RAPL works.

- **Kepler on its own:** Kepler ignores the old key and logs the unknown-field warning. The
  `--experimental.hwmon.enabled` flag is now `--experimental.hwmon.force-enabled`, and Kepler won't
  start with the old flag.
- **Kepler Operator:** this affects you if you set the key through an additional ConfigMap on
  operator 0.24.0 (Kepler 0.11.4). The operator drops the old key without a warning
  ([#676](https://github.com/sustainable-computing-io/kepler-operator/pull/676)). Helm installs on
  charts 0.22.2 through 0.24.0 ran Kepler v0.11.0, which had no HWMON support, so there is nothing
  to change there.

To keep HWMON only, set `cpu.preferredMeters: [hwmon]`. If you also tune HWMON `zones` or
`chipRules`, use `experimental.hwmon.forceEnabled: true` instead for now, or Kepler 0.12.0 drops
that tuning. `forceEnabled` works but logs a deprecation warning.

### Xen guests get new label values

Xen guests used to match the QEMU pattern and showed up as `hypervisor="kvm"` with a name-based VM
ID. They now show up as `hypervisor="xen"` with the Xen domain ID
([#2515](https://github.com/sustainable-computing-io/kepler/pull/2515)). If you have dashboards or
alerts for Xen hosts, update them. Domain IDs change when a guest reboots.

## Try it out

**Kepler with Helm:**

```bash
helm upgrade --install kepler oci://quay.io/sustainable_computing_io/charts/kepler \
  --version 0.12.0 \
  --namespace kepler \
  --create-namespace
```

**Kepler Operator with Helm:** the chart creates cert-manager `Issuer` and `Certificate`
resources for its webhooks by default (`webhooks.certManager.enabled: true`), so install
[cert-manager](https://cert-manager.io/docs/installation/) first. Without it, the install fails.
The operator also needs the Prometheus Operator `ServiceMonitor` CRD. See the operator's
[Kubernetes prerequisites](https://github.com/sustainable-computing-io/kepler-operator/blob/v0.25.0/docs/user/installation/kubernetes.md#prerequisites).

```bash
helm upgrade --install kepler-operator \
  oci://quay.io/sustainable_computing_io/charts/kepler-operator \
  --version 0.25.0 \
  --namespace kepler-operator \
  --create-namespace
```

**OpenShift:** Kepler Operator 0.25.0 is in the Community Operators catalog. With automatic
approval, OLM upgrades for you. Otherwise, approve the pending InstallPlan.

Back up your `PowerMonitor` first, and see the
[upgrade guide](https://github.com/sustainable-computing-io/kepler-operator/blob/v0.25.0/docs/user/guides/upgrading.md)
for details. Still on the legacy `Kepler` resource? Do the
[migration to PowerMonitor](https://github.com/sustainable-computing-io/kepler-operator/blob/v0.25.0/docs/user/guides/migration.md) first.
